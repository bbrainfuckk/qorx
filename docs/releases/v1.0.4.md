# Qorx v1.0.4

Qorx v1.0.4 is a clarity and packaging release on top of v1.0.3.

## What Changed

- Rewrote the README opening around the felt problem: AI workflows repeatedly
  paste the same local files into prompts.
- Described `.qorx` as a small domain-specific language and runtime, not a
  broad general-purpose app language.
- Added the first real language-program slice: `let` bindings, named resolver
  steps, `cache ... key ... ttl ...`, `assert supported(...)`, `emit`,
  `qorx-check`, AST/QIR compiler reports, protobuf bytecode opcodes, `qstk`
  stack tape, and local interpreter execution.
- Replaced the first example with a practical resolver-boundary question.
- Surfaced the self-benchmark table in the README so readers can see the local
  before/after numbers without digging through the benchmark folder.
- Added short Qorx terms such as `qrk`, `qosm`, `qshf`, `hzon`, `qpak`, `qalc`,
  and `qstk` while keeping the physics language behind concrete workflow proof.
- Bumped package and distribution metadata from `1.0.3` to `1.0.4`.

## Boundary

This release does not add a new compression claim. Qorx still claims local
context resolution only when the resolver is available. The benchmark numbers
are deterministic local `ceil(chars / 4)` estimates, not provider invoice
savings.

This release also does not claim SaaS readiness. See
[`docs/PRODUCTION.md`](../PRODUCTION.md) for the production boundary.
